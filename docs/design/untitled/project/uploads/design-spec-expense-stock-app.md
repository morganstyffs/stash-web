# Design Spec — เว็บแอปบันทึกรายรับ-รายจ่าย + กึ่งระบบสต็อก

เอกสารสรุปดีไซน์ทั้งหมดเพื่อยกไปทำต่อใน Claude Design แล้วส่ง Claude Code สร้างจริง

---

## 1. ภาพรวมโปรเจกต์

แอปบันทึกรายรับ-รายจ่ายส่วนตัว ที่ผนวก "กึ่งระบบสต็อกสินค้า" สำหรับธุรกิจขายต่อ (resale) — ทุกการซื้อสินค้าเข้าจะบันทึกเป็นรายจ่าย + สร้างสินค้าในสต็อกพร้อมกันในครั้งเดียว

- ผู้ใช้หลัก: ส่วนตัว / ผู้ใช้คนเดียว (ไม่มีระบบ multi-user, สิทธิ์, แชร์ ใน MVP)
- แพลตฟอร์ม: mobile / tablet-first, ทำเป็น PWA, offline-first (บันทึกได้แม้ไม่มีเน็ตแล้วซิงก์ทีหลัง)
- หลักการหลัก 3 ข้อ:
  1. บันทึกเร็วที่สุด — ทุกดีไซน์วนรอบ "ลดแรงเสียดทานตอนบันทึก"
  2. AI เป็นแชทด้านข้าง — พิมพ์/พูดสั่งงาน + อัปโหลดรูป/ไฟล์ได้ และลงมือทำจริง
  3. รายจ่ายซื้อสินค้า → ลงสต็อกอัตโนมัติ ไม่ทำงานซ้ำซ้อน

---

## 2. Design System

### โทนและทิศทาง
สว่าง สบายตา เป็นมิตรแต่พรีเมียม หลุดจาก "การ์ดเรียงกัน" แบบเทมเพลต AI โดยใช้: ฮีโร่ทรง "กระเป๋า/pocket" ขอบเส้นประ, แถวข้อมูลแบบ ledger (มีเส้นคั่น hairline) แทนการ์ดลอย, และสีแบรนด์เดียวที่กล้ายืนหยัด

สไตล์: flat ล้วน — ไม่มี gradient, ไม่มี shadow หนัก, ขอบบาง 0.5px, ช่องไฟเยอะ, หัวเรื่องแบบ sentence case

### สีแบรนด์ (มินต์)
| บทบาท | ค่า | ใช้ตอนไหน |
|---|---|---|
| Mint bright | `#2CC0A0` | เส้นกราฟ, จุดเน้น, ไอคอน accent |
| Mint deep | `#0E7D66` | ปุ่มหลัก, ฮีโร่กระเป๋า, nav active (พื้นเข้ม + ตัวอักษรขาว) |
| Mint tint | `#E1F6F0` | พื้นแท็ก/ชิปที่เลือก, ไฮไลต์อ่อน |
| Mint text-on-tint | `#0C5646` | ตัวอักษรบนพื้น tint/สว่าง |
| Mint on-hero badge | `#C9F2E7` | badge บวกบนฮีโร่พื้นเข้ม |

หมายเหตุ contrast: สีมินต์สว่างเวลาทำปุ่มทึบตัวอักษรขาว ให้ใช้เฉดเข้ม `#0E7D66` เสมอ ส่วนมินต์สว่าง `#2CC0A0` ใช้กับพื้นไฮไลต์/กราฟ/ตัวอักษรเข้ม

### สี semantic และ category
| บทบาท | ค่า |
|---|---|
| รายรับ / บวก | `#1D9E75` |
| รายจ่าย / ลบ | `#E24B4A` |
| เตือน / รอดำเนินการ | `#BA7517` |
| Category — เหลือง | `#F5C64C` (ตัวอักษร `#4A3A08`) |
| Category — คอรัล | `#FB7A57` (ตัวอักษร `#7A2F17`) |
| Category — เขียว | `#34C471` (ตัวอักษร `#0B3D22`) |
| Category — ดำ | `#171717` (ตัวอักษร `#E8E8E8`) |

### ตัวอักษร
- ฟอนต์เดียวทั้งระบบ: **Prompt** (Google Fonts) น้ำหนัก 400 (ปกติ) และ 500 (เน้น) เท่านั้น
- ตัวเลขเงินทั้งหมดเปิด tabular figures: `font-feature-settings: 'tnum'` เพื่อให้เรียงหลักตรงในตาราง
- ขนาดอ้างอิง: ยอดฮีโร่ ~30px/500, หัวข้อ section ~15-16px/500, body ~13px, label ~11px/muted

### รูปทรงและระยะ
- Radius: card 12-16px, ฮีโร่กระเป๋า 18px, ปุ่ม 13-14px, input 10px, pill 20px
- ฮีโร่กระเป๋า: พื้น mint deep + กรอบเส้นประ `1.5px dashed rgba(255,255,255,0.2)` เว้นใน 5-6px
- แถวรายการ (ledger): คั่นด้วย hairline `0.5px` ไม่ใช้การ์ดลอย
- ไอคอน: Tabler outline

| category_id | fk | → categories |
| wallet_id | fk | → wallets |
| date | date | |
| note | text | |
| is_stock_purchase | bool | ทำเครื่องหมายว่าเป็นการซื้อสินค้าเข้า |
| stock_item_id | fk null | ลิงก์ไปสินค้าที่สร้าง/ขาย |
| created_at | timestamptz | |

### `categories`
| ฟิลด์ | ชนิด | หมายเหตุ |
|---|---|---|
| id | uuid | PK |
| name | text | |
| kind | enum | `income` / `expense` |
| is_stock_category | bool | ถ้า true → บันทึกในหมวดนี้จะเปิดฟอร์มสินค้าอัตโนมัติ |
| icon | text | ชื่อไอคอน Tabler |
| color | text | |

### `wallets`
id, name, type (cash/bank/promptpay), balance

### `stock_items`
| ฟิลด์ | ชนิด | หมายเหตุ |
|---|---|---|
| id | uuid | PK |
| name | text | |
| category | text | ประเภท (เสื้อ/รองเท้า/...) |
| brand | text | |
| size | text | |
| color | text | |
| condition | enum | ใหม่ / มือสอง-ดี / มีตำหนิ |
| cost_per_unit | numeric | ต้นทุน/ชิ้น (จากรายจ่ายต้นทาง) |
| qty_total | int | จำนวนที่รับเข้า |
| qty_remaining | int | คงเหลือ |
| target_price | numeric | ราคาตั้งขาย/ชิ้น |
| sku | text | สร้างอัตโนมัติ เช่น `STZ-NIK-0042` |
| status | enum | `in_stock` / `partial` / `sold` |
| needs_details | bool | true = "รอเติมรายละเอียด" |
| photos | text[] | |
| source_transaction_id | fk | รายจ่ายที่สร้างสินค้านี้ |
| created_at | timestamptz | |

### `stock_sales`
เชื่อมรายรับ (income transaction) กับสินค้า: sale_transaction_id, stock_item_id, qty_sold, sale_price, profit (= sale_price − cost_per_unit)

### `favorites`
id, label, amount, category_id (สำหรับรายการโปรดแตะเดียวจบ)

### `recurring`
id, template (type/amount/category), schedule (สำหรับรายการประจำอัตโนมัติ)

### กติกาการซิงก์ (สำคัญ)
1. **ซื้อเข้า**: บันทึกรายจ่ายในหมวดที่ `is_stock_category = true` → สร้าง `stock_items` (cost_per_unit, qty จากฟอร์ม) + ลิงก์ `source_transaction_id`
2. **ขายออก**: บันทึกรายรับที่ผูกสินค้า → `qty_remaining -= qty_sold`, สร้าง `stock_sales`, คำนวณ profit อัตโนมัติ, อัปเดต status
3. **ตัวเลือก (แนะนำ)**: ให้ "ซื้อสต็อก" เป็นประเภท *สินทรัพย์ (inventory)* แยกจาก "รายจ่ายที่ใช้หมดไป" เพื่อให้กราฟหมวดใช้จ่ายไม่เพี้ยนตอนลงของเยอะ และรับรู้กำไรตอนขายจริง

## 5. ฟีเจอร์ (แบ่งชั้น)

### Core (MVP)
บันทึกรายรับ/รายจ่าย + หมวด + แท็ก, งบประมาณต่อหมวด, รายงาน/กราฟ, รายการประจำ (recurring), หลายกระเป๋าเงิน + หลายสกุลเงิน, เตือนบิล

### Standout
สแกนสลิป/ใบเสร็จ (OCR), รายการโปรดแตะเดียวจบ, "เหลือใช้ได้ (safe-to-spend)", เตือนอัตราการใช้จ่าย (pace), ตัวจัดการ subscription

### AI Layer (4 รูปแบบ)
1. จัดหมวดอัตโนมัติ (predictive) — พื้นฐาน
2. ผู้ช่วยสนทนา — ถาม insight ("เดือนนี้ค่ากินไปเท่าไหร่")
3. AI ช่วยป้อนข้อมูล — พิมพ์/พูด/สแกน → รายการ (ตรงกับ "บันทึกเร็วสุด" มากสุด)
4. เชิงรุก/agentic — พยากรณ์, จับรายการผิดปกติ, เสนอปรับงบ (ระยะยาว)

รวมถึง: สร้างสินค้าสต็อกจากข้อความ ("ซื้อเสื้อ Nike 3 ตัว ตัวละ 400 ตั้งขาย 890")

### Stock / Resale
ซื้อเข้า→สร้างสต็อกอัตโนมัติ, โหมดรวบรวมต่อเนื่อง, คิวรอเติมรายละเอียด, มูลค่าสต็อก + กำไรรอขาย, ขายออก→ตัดสต็อก+คำนวณกำไร (future)

### Future / Phase 2
อ่านจาก LINE/SMS ธนาคาร, จอขายออก, รายละเอียดสินค้า, multi-user

## 6. AI Layer — รายละเอียดเชิงเทคนิค

- รูปแบบ: แชทด้านข้าง (side panel/slide-over) รับภาษาธรรมชาติ → แปลงเป็น action
- ความสามารถ: บันทึกจากข้อความ/เสียง, สแกนสลิป/รูป→รายการ, สร้างสินค้าสต็อกจากข้อความ, ตอบคำถาม insight จากข้อมูลจริง
- เทคนิค: Claude API + structured output (JSON) / function calling ให้คืนค่าโครงสร้างรายการ, ใช้ประวัติธุรกรรมประกอบ (RAG)
- ความเป็นส่วนตัว: มีสวิตช์ปิดฟีเจอร์ AI ได้; แจ้งผู้ใช้ว่าข้อความธุรกรรมจะผ่าน prompt ของโมเดลเมื่อใช้แชท

## 7. Tech Stack

- Frontend: React 18 + Supabase (SPA / PWA, offline-first)
- AI: Claude API (structured output / function calling)
- ฟอนต์: Prompt ผ่าน Google Fonts
- หลักปฏิบัติ: additive-only migrations (รันมือใน Supabase SQL Editor), แยก branch/PR ต่องาน, Plan Mode ก่อน implement, ขออนุมัติก่อน merge/แก้ schema

---

## 8. หลักการ UX (ยึดตลอด)

- บันทึกด้วยนิ้วโป้งข้างเดียว: ปุ่ม + ลอยกลาง, keypad-first, รายการโปรด, ทางลัดใช้บ่อย
- Offline-first: บันทึกได้แม้ไม่มีเน็ต
- ฮีโร่ชู "เหลือใช้ได้" แทนยอดคงเหลือ เพื่อคุมการใช้จ่าย
- สต็อก: ซื้อสินค้า→ลงสต็อกอัตโนมัติตามหมวด, เซฟครั้งเดียวได้ทั้งรายจ่าย+สต็อก, กรอกไม่ครบก็ทำต่อได้ (รอเติมรายละเอียด)

---

## 9. วิธีใช้เอกสารนี้ต่อ

1. **Claude Design** — เปิดงานใหม่ด้วย design system ในข้อ 2 (สีมินต์ + Prompt + สไตล์ pocket/ledger) แล้วทำหน้าที่ยังเป็น wireframe/spec ให้เป็น hi-fi: ประวัติ, งบประมาณ, ตั้งค่า, คิวรอเติมรายละเอียด
2. **Claude Code** — สร้างจริงบน React + Supabase ตาม data model ข้อ 3 และ navigation ข้อ 4; เริ่มจาก schema (additive) → หน้าหลัก + เพิ่มรายการ → สต็อก → แชท AI
