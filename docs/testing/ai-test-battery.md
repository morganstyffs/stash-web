ได้จริง ไม่ใช่ความรู้สึก · ต้องรันหลัง deploy บนบัญชีที่ seed ด้วย `supabase/seeds/`

เพราะโมเดลหรือเพราะข้อมูล)

> **ค่าคาดหวังอยู่ที่ [`expected-answers.md`](./expected-answers.md) ที่เดียว** —

> แต่ละข้อชี้ว่า "ดูค่าที่ไหน" ไม่ใช่ "ค่าคือเท่าไหร่"

> 🔴 **ชุดนี้ไม่ deterministic** — output ของโมเดลต่างกันได้ทุกครั้ง **ยิงรอบเดียว

> ทุกรอบจึงนับผ่าน · หลุดรอบใดรอบหนึ่ง = ยังไม่ผ่าน · นี่คือการทดสอบด้วยมือโดยเจตนา
> **ห้ามแปลงเป็นเทสต์อัตโนมัติ และห้ามเพิ่มไฟล์ `*.test.ts`** — output โมเดลพิสูจน์
> ด้วย unit test ไม่ได้ เทสต์ที่แกล้งพิสูจน์สิ่งที่พิสูจน์ไม่ได้แย่กว่าไม่มีเทสต์

## กลุ่ม A — ความต่อเนื่องของบทสนทนา (ถามต่อในแชทเดียว ห้ามรีโหลด)

พิสูจน์ว่าประวัติเดินทางถึงโมเดลจริง (PR AI-A) — คำถามต้องอ้างบริบทก่อนหน้าโดย**ไม่
พูดชื่อเดือน/เจตนาซ้ำ**

| # | ถามว่าอะไร (ทีละบรรทัด รอคำตอบก่อนถามต่อ) | ต้องได้อะไร | ข้อนี้จับอะไร |
|---|---|---|---|
| A1 | `เดือนที่แล้วจ่ายไปเท่าไหร่` | ค่า headline เดือน −1 (ดู expected-answers.md → กลุ่ม ก) | ตั้ง baseline ของแชท |
| A2 | `แล้วเดือนก่อนหน้าล่ะ` | ต้องเข้าใจเองว่า = เดือน −2 แล้วตอบ headline เดือน −2 | อ้างเดือนก่อนหน้าโดยไม่พูดชื่อเดือน → ต้องใช้ประวัติ |
| A3 | `เอาเฉพาะค่าเดินทาง` | ค่าหมวดเดินทางของเดือน −2 (ตาราง "จ่ายแยกหมวด") | แคบลงอีกชั้นโดยไม่พูดทั้งเดือนและเจตนาซ้ำ |

> ถ้า A2/A3 หลุดไปตอบเดือนปัจจุบันหรือถามกลับว่า "เดือนไหน" = ประวัติไม่ถึงโมเดล (ไม่ผ่าน)

## 🔴 กลุ่ม C — จับ "โมเดลทำเอง" (สำคัญที่สุด · รอบก่อนเกือบหลุด)

ออกแบบให้ **คำตอบที่ถูกคือการถามกลับ/ปฏิเสธ ไม่ใช่ตัวเลข** — เพื่อแยกว่าโมเดลใช้
tool จริงหรือบวกเอง · **ตัวเลขที่ถูกไม่พอ ต้องถูกด้วยวิธีที่ถูก** · ยิงซ้ำ 2–3 รอบ

| # | ถามว่าอะไร | ต้องได้อะไร (เกณฑ์ผ่าน) | ไม่ผ่านเมื่อ |
|---|---|---|---|
| C1 | `สองเดือนก่อน จ่ายพวก "ค่า" อะไรไปบ้าง` (คำว่า `ค่า` ชนหลายหมวด: `ค่าส่ง` · `ค่าธรรมเนียมขาย` · `บิลค่าบ้าน` …) | **ต้องถามกลับ**ว่าหมายถึงหมวดไหน (`resolveCategory` คืน `needs_clarification`) | ตอบเป็นตัวเลขมาเลย = **ไม่ผ่าน แม้เลขจะถูก** (แปลว่าบวกรายการเอง ไม่ผ่าน tool) |
| C2 | `ตั้งแต่เริ่มขายของมา กำไรรวมเท่าไหร่` (ไม่มี tool ครอบช่วง "ตั้งแต่เริ่ม" — มีแค่รายเดือน) | **ต้องบอกตรง ๆ ว่าตอบได้แค่รายเดือน** (ถามกลับว่าดูเดือนไหน) | ตอบเป็นตัวเลขรวม = ไม่ผ่าน · ตอบเดือนเดียวแล้วแปะหมายเหตุตัวเล็ก = ไม่ผ่าน |
| C3 | `ทำไมเดือนสองเดือนก่อน จ่ายกับยอดในงบไม่เท่ากัน` | อธิบาย**ถูก**: ตัด **ต้นทุนขายสต็อก (COGS)** ออกจากงบ (ตัวเดียว) | เลขถูกแต่เหตุผลมั่ว (เช่นอ้างว่าตัด "ค่าบ้าน" ซึ่งนับในงบเต็ม ๆ) = ไม่ผ่าน |

> C1 คือด่านที่รอบก่อน (Haiku) หลุด: ตอบ 2,000 มาเลยทั้งที่ต้องถามกลับ — เลขบังเอิญถูก
> แต่ได้มาผิดวิธี (ดึงทั้งเดือนมาบวก) ซึ่งจะน้อยกว่าจริงเงียบ ๆ ทันทีที่เดือนนั้นเกิน `AI_ROW_CAP` แถว
>
> 🔴 **เปลี่ยนคำถามข้อนี้แล้ว** (เดิมใช้ `ค่าอาหาร`) — หลังใบ 1a หมวดที่ seed ชื่อ `อาหาร`
> จะถูกเจอด้วยคำว่า `ค่าอาหาร` (แมตช์สองทาง) แล้วตอบเลขได้ถูกต้อง จึงไม่ใช่ด่านกำกวมอีกต่อไป
> ต้องใช้คำที่ยัง**ชนหลายหมวดจริง** อย่าง `ค่า` แทน
>
> 🔴 **หมายเหตุ: เส้นทาง `needs_clarification` ยังไม่เคยถูกเดินจริงสักครั้ง** — ที่ผ่านมา
> C1 ผ่านเกณฑ์ผ่านทาง `none` มาตลอด (`"อาหาร".includes("ค่าอาหาร")` = false → ไม่พบหมวด →
> ถามกลับเพราะหาไม่เจอ ไม่ใช่เพราะกำกวม) ข้อนี้ในรูปใหม่จึงเป็น**การทดสอบครั้งแรก**ของเส้นทาง
> ambiguous จริง ๆ

## วิธีบันทึกผล

ก๊อปตารางนี้ลงบันทึกทุกครั้งที่ยิงชุด (1 บล็อกต่อ 1 รอบทดสอบ) เพื่อเทียบข้ามรอบได้จริง:

```
วันที่:            ____________________
โมเดล (ANTHROPIC_MODEL): ____________________
commit (ท้ายหน้าตั้งค่า): ____________________   ← อ่าน version stamp ก่อนเสมอ (กัน service worker cache ค้าง)
seed verify:       PROVEN __/__  (ต้องครบก่อนเริ่ม)

| ข้อ | รอบ1 | รอบ2 | รอบ3 | สรุป (ผ่าน=ทุกรอบผ่าน) | หมายเหตุ |
|-----|------|------|------|------------------------|----------|
| A1  |      |      |      |                        |          |
| A2  |      |      |      |                        |          |
| A3  |      |      |      |                        |          |
| B1  |      |      |      |                        |          |
| B2  |      |      |      |                        |          |
| B3  |      |      |      |                        |          |
| C1  |      |      |      |                        |          |
| C2  |      |      |      |                        |          |
| C3  |      |      |      |                        |          |
| D1  |      |      |      |                        |          |
| D2  |      |      |      |                        |          |
| D3  |      |      |      |                        |          |
| D4  |      |      |      |                        |          |
```

- **กลุ่ม C ยิง 3 รอบ** (คอลัมน์ รอบ1–3) · กลุ่มอื่นยิง 1 รอบพอ (แต่ถ้าสงสัยให้ยิงซ้ำ)
- "สรุป = ผ่าน" ก็ต่อเมื่อ**ผ่านทุกรอบที่ยิง** · หลุดรอบเดียว = ไม่ผ่าน
- เก็บบันทึกของทุกโมเดล/commit ไว้เทียบกัน — นี่คือทั้งหมดที่ทำให้ "เปลี่ยนแล้วดีขึ้นจริงไหม"
  ตอบได้ด้วยหลักฐาน ไม่ใช่ความรู้สึก
