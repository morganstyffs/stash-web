## 🟡 กลุ่ม ข — ขึ้นกับ "วันนี้วันที่เท่าไหร่" · เขียนเป็นสูตร ห้าม hardcode

พิสูจน์อัตโนมัติไม่ได้ เพราะเปลี่ยนทุกวัน — ถ้าไป hardcode มันจะ FAILED ทุกวันถัดไป
แล้วคนจะเลิกเชื่อไฟล์ verify ทั้งไฟล์ จึงเว้นออกจาก `verify_test_data.sql` โดยตั้งใจ

| ถามประมาณว่า | tool | สูตร (ไม่ใช่ตัวเลข) |
|---|---|---|
| เดือนนี้เหลืออีกกี่วัน | home_summary.days_left | จำนวนวันที่เหลือในเดือน **รวมวันนี้** (ปฏิทินไทย) |
| เดือนนี้ใช้ได้วันละเท่าไหร่ | home_summary.daily_allowance | `safe_to_spend(เดือนนี้) ÷ days_left` = **23,200 ÷ days_left** |
| ของค้างในสต็อกนานสุดกี่วัน | stale_stock | `วันนี้ − (วันแรกของเดือน −3 + 1 วัน)` (กระเป๋า C / หมวก D สร้างเดือน −3) |
| ทุนจมในของค้าง | stale_stock (computeSunkCost) | Σ(จำนวนคงเหลือ × ทุน) ของชิ้นค้าง >60 วัน — **อย่างน้อย** กระเป๋า C (3×300) + หมวก D (2×250) = 1,400 (รองเท้า A ที่เหลือ 6 ชิ้นอยู่เดือน −2 → ~30–60 วัน อาจนับเพิ่มใกล้ขอบเดือน) |

> "safe_to_spend เดือนนี้ = 23,200" เป็นค่าคงที่ (กลุ่ม ก) แต่ `daily_allowance` ที่หารด้วย
> `days_left` เป็นกลุ่ม ข เพราะตัวหารเปลี่ยนทุกวัน

## 🟢 บทสนทนาต่อเนื่อง (multi-turn) — ทดสอบว่าประวัติถึงโมเดลจริง (ใบ AI-A)

ถามทีละบรรทัด รอคำตอบก่อนถามต่อ — คำตอบต้องอ้าง **บริบทเดิม** ไม่ใช่เริ่มใหม่

1. `เดือนที่แล้วจ่ายไปเท่าไหร่` → ~10,000
2. `แล้วเดือนก่อนหน้าล่ะ` → ต้องเข้าใจว่า = เดือน −2 → ~9,000
3. `เอาเฉพาะค่าเดินทาง` → เดือน −2 หมวดเดินทาง → ~1,000

อีกชุด (ทดสอบ **หมวดชื่อใกล้กัน** case #7):

1. `เดือนนี้จ่ายค่าอาหารเท่าไหร่` → มีหมวด **อาหาร** และ **อาหารสัตว์** ใกล้กัน →
   AI **ต้องถามกลับ** ว่าหมายถึงหมวดไหน (ห้ามเดา)
2. `อาหารสัตว์` → ~300 · หรือตอบ `อาหาร` → ~5,000
